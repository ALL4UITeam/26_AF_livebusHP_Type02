# LIVEBUS B안 — 한 대의 버스와 함께 이어지는 여정 (3차)

LIVEBUS 첫 등장 → 출발 → BMS → BIT → BIS → LIVEBUS 마무리까지, 같은 버스 한 대와 같은 도시 안에서 이어진다.
이전 상태: 2차는 `concept-b-v2.html` + `src/concept-b-journey-v2/`, 1차는 `concept-b-v1.html` + `src/concept-b-journey-v1/`.

## 3차에 더한 것
- 진행률을 0~2.3 으로 늘렸다. **0~1 은 2차와 똑같은 구도·타이밍**이고(화면 높이의 5.8배 = 진행률 1), 1~2.3 이 새 구간이다.
  1.0~1.38 BMS 에서 정류장으로 하강·감속·정차 / 1.38~1.52 BIT / 1.52~1.62 옆으로 이동 / 1.62~1.84 BIS / 1.86 재출발 / 2.16~2.3 마무리.
- 버스: 1.197 부터 감속해 1.38 에 x = 498.16 에 정차, 1.86 에 다시 출발. 바깥 차로로 옮겼다가 돌아온다(`laneZ`). 바퀴는 이동 거리만큼만 돈다.
- `stop.js`: 쉘터, 태양광 BIT 안내기, 스마트폰, 버스 → 안내기 → 스마트폰으로 이어지는 빛, 지나온 노선의 빛.
- 화면 상태는 진행률로만 정해진다. BIT: 4분 후 → 2분 후(1.09) → 곧 도착(1.22) → 도착(1.372) → 출발 뒤 12분 후(1.9).
  스마트폰: 노선(1.54~1.64) → 버스 위치(1.64~1.7) → 정보 영역(1.69~1.76), 선택한 정류장은 '도착' → 재출발 뒤 '출발', 다음 정류장은 3분 → 2분 → 1분.
- 동작 줄이기: 다섯 구도(0, 1, 1.45, 1.74, 2.3)를 짧은 페이드로 바꾼다.

## 확인이 필요한 것
- **BIT 형태**: 브로슈어가 작업 환경에 없어 요청서에 적힌 구조(기울어진 직사각형 태양광 패널 · 세로형 화면 · 지주 · 받침)만으로 만들었다. 치수·비례·세부는 브로슈어를 받아 `stop.js` 의 BIT 부분을 맞춰야 한다.
- **CTA**: 연결할 서비스 소개 주소가 정해지지 않아 링크를 걸지 않았다(`concept-b.html` 의 `.cta`, "연결 주소 미정" 표시). 정해지면 `<a href>` 로 바꾼다.
- 노선·정류장 이름과 도착 시간은 시연용 예시다(`stop.js` 의 `ROUTE`).

# LIVEBUS B안 — 한 대의 버스와 함께 이어지는 여정 (2차)

"버스의 움직임을, 모두의 정보로." 같은 버스 한 대를 따라 오프닝 → 첫 화면 → 출발 → 도시 진입 → BMS 로 이어지는 3D 스크롤 경험.
1차 상태는 `concept-b-v1.html` 과 `src/concept-b-journey-v1/` 에 그대로 있다(비교용).

## 보기
`npm run dev` 후 `/concept-b.html`. three.js r128 을 cdnjs 에서 불러온다(패키지 설치 없음). `vite build` 대상에는 넣지 않았다.

## 구성
- **오프닝(약 2.3초, 시간 기준)**: 어둠 속 실루엣 → 0.55초 전조등 → 0.6~1.6초 빛이 앞에서 뒤로 훑으며 차체가 드러남 → 1.1초 바닥 파동, 카메라가 가장 빠르게 물러나는 순간 → 정착 후 문구.
  스크롤 구도 위에 덧붙는 변화라서 도중에 스크롤하면 기다림 없이 이어진다.
- **스크롤 진행률 p** 하나가 이동 거리·바퀴 회전·카메라·세계가 열리는 반경·신호·문구를 정한다.
  0~0.09 첫 화면 / 0.09~0.18 출발 준비(전조등, 앞쪽 도로) / 0.18~0.47 측면 주행 / 0.47~0.76 도시 진입, 뒤쪽 상공 / 0.76~1 BMS.
- **세계는 처음부터 만들어져 있고**, 버스에서 가까운 곳부터 보이는 반경만 넓어진다(`reveal`). 구조는 고정, 신호만 움직인다.
- 아직 없는 것: BIT, BIS, 마무리 장면과 CTA.

## 파일
```
concept-b.html                       마크업, 문구, 로고 SVG, 글꼴·three.js 불러오기
src/concept-b-journey/main.js        진행률, 카메라 구도(KEYS)와 보간, 오프닝, 입력, 문구
src/concept-b-journey/bus.js         버스: 수식으로 만든 곡면 차체 + 곡면에 얹은 유리·문·램프·패널 선, 독립 바퀴
src/concept-b-journey/world.js       도로·인도·표시·가로등·가로수·건물·먼 윤곽·다른 버스·연결망·신호
src/concept-b-journey/journey.css    글자, 문구 등장·퇴장, 커서, 로딩, 대체 화면
src/concept-b-journey/poster.jpg     WebGL 을 쓸 수 없을 때의 대표 이미지
```

## 버스 모델의 한계 (GLB 가 필요한 부분)
코드 모델로 한 것: 둥근 모서리와 볼록한 옆면, 뒤로 누운 앞유리, 유리 틀과 기둥, 문 2개, 패널 선, 휘어 내려오는 사이드미러,
덮개 안의 전조등(주간등 띠 + 원형 렌즈)과 후미등, 두꺼운 타이어와 안으로 들어간 휠, 금속·유리·고무 재질 구분.
코드 모델로 안 되는 것: 실제 실내(지금은 유리에 옅은 무늬로 암시만 한다), 바퀴집의 실제 깊이(어두운 면으로 표현),
곡면이 이어지는 범퍼·필러의 정밀한 면 나눔, 램프 내부의 반사판, 로고 엠블럼, 텍스처(먼지·데칼).
목표 품질에는 정교한 GLB 가 필요하다. 조건: glTF 2.0, 실제 비례(약 11m), 바퀴 4개 분리 노드(축 중심 = 바퀴 중심),
재질 분리, 10만 삼각형·10MB 이하 권장, 상업적 사용 가능 라이선스. `buildBus()` 가 돌려주는 `{ group, wheels, lamps }` 에 맞춰 교체한다.

## 조정값
- 카메라: `main.js` 의 `KEYS`  /  주행: `distanceAt()`  /  오프닝 시간: `frame()` 안의 `oCam`, `oSweep`, `oHead`, `oRipple`
- 세계가 열리는 반경: `main.js` 의 `reveal`  /  먼 윤곽 `far`, 신호 `sig`, 연결망 `net`
- 건물 창·색: `world.js` 의 `buildingMat`  /  다른 버스의 차로와 속도: `lanes`(출발 위치는 서로 겹치지 않게 자동으로 고른다)
- 재질: `bus.js` 의 `M`  /  반사 조명판: `world.js` 의 `buildEnvironment()`
- 확인용: 콘솔에서 `window.__JOURNEY_SEC = 1.2` 로 오프닝의 한 순간을 멈춰 볼 수 있다(`undefined` 로 해제).

## 접근성·성능
- 동작 줄이기: 오프닝과 카메라 이동 없이 두 구도(첫 화면, BMS)를 짧은 페이드로 바꾼다.
- 터치 환경에서는 사용자 커서를 표시하지 않는다. 좁은 화면은 다른 버스·신호·먼 건물 수를 줄인다.
- 프레임이 계속 느리면 해상도 배율을 낮춘다. 한 화면 약 8만 삼각형.
