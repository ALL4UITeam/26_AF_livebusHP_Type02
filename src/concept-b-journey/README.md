# LIVEBUS 서비스 경험 페이지 (`/concept-b.html`) — 6차

한 대의 버스를 따라 **첫 등장 → LIVEBUS → BMS → BIT → BIS → 도입 문의 제안**까지 이어지고, 마지막 버튼이 문의 페이지(`/index.html`)로 간다.
BMS 에서 버스 위에 나타난 **정보 노드**가 정류장까지 함께 가고, 같은 노드에서 BIT 와 BIS 로 정보가 전해진다(아래 '정보 노드', '정보의 전달').
스크롤 진행률 `p`(0 ~ 2.4) 하나가 버스 위치·바퀴·카메라·환경·정보 전달·기기 화면·문구를 모두 정한다. 멈추면 멈추고, 올리면 그대로 되돌아간다.
시간으로 흐르는 것은 첫 로드의 오프닝(약 2.5초), BMS 의 '위치 갱신' 표현, 빛의 아주 약한 밝기 변화뿐이다.

| 파일 | 내용 |
|---|---|
| `main.js` | 진행률과 스크롤 배정(`CUTS`), 카메라 구도(`KEYS`), 오프닝, 정보 노드의 높이·표지·선택, 페이지 이동 기억, 문구 전환 |
| `node.js` | 주인공 버스의 정보 노드(작은 3D 노드, 링크 선, 위치 갱신의 빛) |
| `bus.js` | 주인공 버스. **최종 사용 모델**(한국형 저상 시내버스 참고 디자인). 아래 '버스 모델' 참고 |

| `lines.js` | 선(두께가 있는 띠)과 도트를 그리는 공통 부품 |

| `world-v1.js`, `stop-v1.js` | 이전 도시 배경·효과(보존본). `concept-b.html?city=v1` 로 바꿔 볼 수 있다 |
| `stop.js` | 태양광 BIT, 쉘터, 스마트폰, 노드에서 기기로 전해지는 빛, 구간(`TL`)과 전달 단계(`PH`) |
| `journey.css` | 문구·진행 내비게이션·버튼·반응형 |

## 진행률과 장면
| p | 장면 | 문구가 보이는 구간 |
|---|---|---|
| 0 ~ 0.09 | LIVEBUS(첫 화면) | ~ 0.075 |
| 0.09 ~ 0.76 | 출발 → 측면 주행 → 도시 진입 | – |
| 0.76 ~ 1.0 | BMS(도시 전체) | 0.755 ~ 1.03 |
| 1.0 ~ 1.34 | 내려가며 감속. 1.34 에 구도가 먼저 정착하고 버스가 굴러 들어와 1.38 에 정차 | – |
| 1.34 ~ 1.54 | BIT. 1.385 ~ 1.545 가 BIT 전달 구간 | 1.36 ~ 1.535 |
| 1.54 ~ 1.66 | 물러나며 스마트폰이 올라온다 | – |
| 1.66 ~ 1.9 | BIS. 1.655 ~ 1.885 가 BIS 전달 구간 | 1.67 ~ 1.88 |
| 1.9 ~ 2.22 | 스마트폰이 내려가고 같은 버스가 다시 출발 | – |
| 2.22 ~ 2.4 | CONTACT(도입 문의 제안) | 2.2 ~ |

진행률의 값(구도·문구·주행)은 그대로 두고, **스크롤 거리만** 다시 배정했다(`main.js` 의 `CUTS`, `toS`·`toP`).
화면 높이의 5.8배가 진행률 1 인 것은 같고, BIT 전달 구간은 1.9배, BIS 전달 구간은 1.45배 길게 스크롤한다
→ BIT 전달에 화면 높이의 약 1.76배, BIS 전달에 약 1.93배. 전체 스크롤 길이 2.6475(`.scroll-space` 높이 1636vh, 이전 1492vh).
큰 카메라 이동(BMS → 정류장 1.0 ~ 1.34, BIT → BIS 1.54 ~ 1.66)은 전달 구간 밖에 있다.
진행 내비게이션의 BIT·BIS 버튼과 동작 줄이기의 정지 위치는 정보가 갱신된 뒤(1.52, 1.85)다.

## 정보 노드 — `node.js`, `main.js`
이 버스의 **위치·운행 정보를 나타내는 시각적 표식**이다. 차량에 달린 장치가 아니다.

- 구성: 지붕의 실제 위치(안테나 끝 `SIGNAL`)에서 올라가는 가는 링크 선 → 작은 3D 노드(팔면체, 선명한 시안) → 옆의 작은 표지(`01`, `운행 중`/`도착`).
  표지는 HTML 버튼(`.node-tag`)이고 3D 노드의 화면 위치를 따라간다.
- 보이는 구간: 0.64 ~ 0.84 에 나타나 BMS → 하강 → BIT → BIS 내내 **같은 노드**로 남는다(사라졌다가 새로 생기지 않는다). 버스가 다시 떠나는 1.92 ~ 2.04 에 물러난다.
- 높이: BMS 13.6m → 정류장 5.1m(세로 화면은 BIT 5.6m, BIS 4.2m — 위쪽 문구와 겹치지 않게). 크기는 화면에서 거의 일정하다(반지름 약 8.5 → 12px).
- 다른 버스: 지붕에서 올라가는 짧고 어두운 선과 작은 도트(`world.js`). 내려가는 동안 노선 강조와 함께 사라지고 주인공의 노드만 남는다.
- 위치 갱신(BMS 에서만, 3.6초에 한 번): 지붕의 작은 신호 → 링크 선을 따라 올라가는 빛 → 노드의 부드러운 반응 → 이 차량 둘레의 노선 구간이 잠깐 밝아진다(`uPing`). 큰 동심원·섬광 없음, 다른 차량은 함께 깜빡이지 않는다.
- 선택: 버스나 표지에 마우스를 올리거나, 표지에 키보드 초점(Tab)을 주거나, 모바일에서 탭 → 노드·링크 선·노선이 함께 강조되고 짧은 정보(노선번호·행선, 운행 상태, 다음 정류장)가 펼쳐진다.
  벗어나거나 Esc, 다른 곳을 누르면 기본 상태로 돌아간다. 내용은 `stop.js` 의 `ROUTE`(시연용 예시)에서 가져와 BIT·스마트폰 화면과 같은 값이다(달리는 동안 다음 정류장 = 라이브 정류장, 정차 뒤 = 도서관).
- 정류장에서는 표지를 노드 위쪽으로 올려, 노드에서 떠나는 빛의 경로가 글자를 지나지 않게 한다. 스마트폰의 화면 속 자리와 겹치면 표지를 숨긴다(3D 노드는 깊이 판정으로 가려진다).

## 정보의 전달 — `stop.js` 의 `TL`, `PH`
같은 버스의 정보가 BIT 와 BIS 에 **각각** 제공되는 모습이다. 빛은 버스 위의 노드에서 출발하고, 노드는 날아가지 않고 버스 위에 남는다. **BIT 에서 스마트폰으로 가는 선은 없다.**
전달의 모든 상태는 그 구간 안에서의 스크롤 진행률 `u`(0 ~ 1) 하나로 정해진다(`transferU(p)`). 시간에 따라 쌓이는 값이 없다.

| u | 단계 | 화면 |
|---|---|---|
| 0 ~ 0.2 | 구도 정착, 경로 형성 | 노드가 약간 밝아지고, 노드에서 기기까지 가느다란 경로가 낮은 밝기로 드러난다 |
| 0.2 ~ 0.6 | 정보 이동 | 부드러운 빛의 구간(앞은 짧게, 뒤는 길게 번지는 잔광)이 경로를 따라 고른 속도로 간다 |
| 0.6 ~ 0.8 | 수신과 갱신 | 수신 지점이 밝아지고 기기 테두리를 따라 얇은 빛이 짧게 퍼진다 → 화면 속 정보가 반응하고 바뀐다(0.62) |
| 0.8 ~ 1 | 확인, 정리 | 바깥 경로와 잔광이 사라지고(0.96 까지) 갱신된 정보만 남는다 |

- **BIT**: 노드 → 안내기 **몸체 옆면**(태양광 패널이 아니다) → 옆 테두리의 얇은 빛 → `01` 줄만 강조 → `곧 도착 → 도착`.
- **BIS**: 같은 노드 → 스마트폰 **테두리**(가로 화면은 왼쪽, 세로 화면은 위쪽)에서 끝남 → 화면 안에서 가장자리 반응 → 위치 핀(`01`, 노드와 같은 색) → 노선 → 도착정보.
- 스크롤을 멈추면 빛도 그 자리에 멈춘다(약한 밝기 변화만 남는다). 올리면 그대로 되돌아가고, 작은 스크롤 변화로 다시 시작하거나 겹치지 않는다. 빠르게 지나가면 지나간 만큼의 상태(도착)가 바로 나온다. 스크롤을 붙잡지 않는다.
- 두 전달 구간은 겹치지 않는다(동시에 강조되지 않는다). BIS 구간에서 BIT 화면은 갱신된 채로 남는다.
- 낮고 완만한 경로, 깊이 판정(차체·기기 뒤로 가면 가려짐), 위치는 '화면에서의 길이'로 재서 곡선에서도 속도가 고르다.
- 동작 줄이기에서는 움직임 없이 갱신된 정보만 보인다.

## 구도
- `KEYS` 의 방위각·거리·높이·시선은 보통 **버스 기준**이고, 정류장 구간에서는 `stopHold(p)` 로 **정류장에 선 버스의 자리**에 고정된다.
- BIT: 안내기는 전경(화면 오른쪽), 버스는 중경, 도시는 배경. 안내기는 선 버스의 앞머리에서 약 10m 앞 인도에 있어 버스 전면과 겹치지 않는다.
  쉘터는 안내기 뒤쪽(브로슈어 표지의 배치)이라 안내기나 문구를 가리지 않는다.
- BIS: 카메라가 물러나 버스는 배경 크기가 되고 BIT 는 중경으로 물러나며, 스마트폰이 버스와 안내기 사이 전경에 선다. 스마트폰은 카메라 기준으로 놓여 화면 속 자리가 흔들리지 않는다.
- 세로로 긴 화면은 `KEYS[i].n`(`BIT_N`, `BIS_N`)의 구도를 쓴다: 문구는 위, 기기는 가운데·아래. 세로 화면의 BIS 는 버스 위의 노드와 안내기가 함께 들어오도록 조금 넓게 본다(화각 43°). 16:10 보다 덜 넓은 가로 화면은 세로 화각을 넓혀 좌우 범위를 지킨다.
- `window.__CAM = { az, r, h, lx, ly, lz, fov, shift }` 를 콘솔에 넣으면 구도를 직접 바꿔 볼 수 있다.

## 오프닝(첫 로드에서 한 번)
0.0 앞머리 모서리·전조등·유리 일부가 화면 가까이(버스가 마지막 10m 를 굴러 들어오고 카메라가 붙어 간다) →
0.25 ~ 1.45 가는 빛이 차체 곡면을 따라 앞에서 뒤로 → 0.6 ~ 2.2 카메라가 물러나며 전면과 측면이 드러난다 →
1.2 ~ 2.2 빛이 노면을 따라 짧게 흐른다 → 1.45 헤더 로고, 1.75 헤드라인 → 2.5 스크롤 시작 구도.
- **첫 로드의 중앙 로고**는 오프닝보다 앞, 불러오는 동안의 검정 화면 정중앙에 있다(`concept-b.html` 의 `.loader`). 받은 `AI LIVEBUS.svg` 의 path 를 그대로 넣었고(색·비율 그대로, 이미지 요청 없음),
  아래의 가는 선은 로고 상자 밖에 띄워 로고의 보이는 형태가 화면 한가운데에 온다. 장면이 준비되면 0.18초에 걸쳐 물러나고 첫 버스 화면으로 이어진다.
  (5차에서 문구 자리에 잘못 넣었던 `.intro-logo` 는 지우고 헤더 로고·헤드라인의 시각을 이전 값으로 되돌렸다.) 헤더·마지막 장면·문의 페이지의 로고는 바꾸지 않았다.
- 스크롤 구도 위에 얹는 변화라서 도중에 스크롤하면 그만큼 옅어지며 합류한다(기다리게 하지 않는다). 끝에서 구도가 정확히 일치한다.
- 재생하지 않는 경우: 뒤로 가기로 돌아왔을 때, 문의 페이지의 '서비스 살펴보기'로 돌아왔을 때, 중간 위치로 복원됐을 때, 동작 줄이기.
- 다시 보려면 주소에 `?opening` 을 붙이거나 맨 위에서 새로 고친다.

## 페이지 연결
- 마지막 장면의 `도입 문의하기`, 상단의 `도입 문의` → `./index.html`(같은 탭).
- 뒤로 가기: 브라우저가 스크롤 위치를 되돌리고, 되돌리지 못한 경우에만 `sessionStorage` 의 `lb:journey-p` 로 복원한다.
- `sessionStorage` 에는 진행률과 '문의 페이지에서 돌아옴' 표시만 둔다(개인정보 없음).

## 도시 배경과 선·도트 (2026-11-26 개선)
버스, 카메라 경로, 서비스 순서, 카피 타이밍, 문의 연결은 그대로다. 비교: `/concept-b.html?city=v1`(이전 배경으로 같은 장면).

**선과 도트의 역할** — 모두 `lines.js` 의 같은 부품으로 그린다.
| 역할 | 어디에 | 표현 |
|---|---|---|
| ① 도시 구조선 | 교차하는 길·뒤쪽 길의 연결망(BMS) | 어둡고 안정적인 청색, 가늘게(0.8~1.5px). 길 하나가 한 줄이라 이음매가 없다 |
| ② 선택 노선 | 주인공 버스가 달리는 길(BMS, 마지막 장면의 지나온 길) | 선명한 시안, 더 굵게(1.3~3.4px). 버스의 실제 경로(차로 변경 포함)를 따라 노면에 놓인다 |
| ③ 이동하는 데이터 | 연결망 위의 작은 신호(BMS), 버스 → BIT · 버스 → 스마트폰(핵심 전달) | 작은 밝은 선두 + 짧은 잔광. 배경 신호는 작고 어둡게, 핵심 전달은 선두 도트와 도착 반응이 따로 있다 |
| ④ 위치 도트 | 다른 버스, 주인공의 표식, 차량의 등 | 선명한 중심 + 절제된 주변 빛. 버스마다 다른 박자로 아주 천천히 숨쉰다 |

- 정리한 것: 큰길 위에 겹쳐 있던 연결망 선(y 0.3)과 마지막 장면의 노면 띠를 **선택 노선 하나**로 합쳤다. 주인공 위의 다면체 표식과 1픽셀 세로선은 도트 + 가는 띠로, 다른 버스의 퍼지는 고리는 도트로 바꿨다.
- 선은 1픽셀 기본 선이 아니라 화면에서 두께를 가진 띠다. 세계에서의 폭을 픽셀로 바꾼 뒤 최소·최대 픽셀로 묶어, 멀어져도 끊기거나 깜빡이지 않고 가까워져도 갑자기 굵어지지 않는다.
  가장자리는 픽셀 거리로 부드럽게 처리한다(블룸 없음).
- 배경 신호는 길마다 속도·박자가 다르고 양 끝에서 서서히 켜지고 꺼진다(끝에서 사라졌다 반대쪽에 튀어나오지 않는다). 수는 줄였다(260 → 30, 모바일 12).
- 핵심 전달의 빛은 '화면에서의 길이'로 위치를 잰다. 멀리서 느리고 카메라 앞에서 갑자기 빨라지지 않는다. 꼬리는 점의 나열이 아니라 이어진 띠다.

**도시**
- 건물은 모서리를 깎은 기둥 하나를 인스턴스로 반복하고(한 번에 그림), 정면은 shader 가 유형·크기에 맞춰 그린다: 낮은 상가 / 콘크리트 업무시설(뚫린 창) / 금속 패널 업무시설(띠 창) / 유리 외벽 고층.
  창은 벽보다 안쪽에 있어 보는 각도에 따라 창틀 안쪽 면이 드러난다. 층 줄눈, 1층 유리면과 출입구 한 칸, 그 위의 띠(글자 없음), 옥상 턱과 설비가 있다.
- 큰길을 바라보는 첫 줄은 정면이 한 선에 맞고, 높이와 폭이 섞인다. 뒤쪽 줄은 중층·고층 위주, 지평선의 윤곽은 단순한 덩어리다.
- 창의 불빛은 건물·층·방 단위의 고정 무늬다(시간에 따라 바뀌지 않는다). 약 3할은 낮은 채도의 따뜻한 색이다.
- 가로등 빛은 도로·연석·인도·건물 아랫부분에 같은 식으로 닿는다. 건물이 땅에 닿는 자리에는 번지는 그늘이 있다. 먼 곳은 옅은 남색 안개로 정리된다.
- 연석(인도보다 밝은 돌), 인도의 포장 줄눈, 가로수 둘레의 흙 자리, 가로등 받침을 더했다.
- 가까운 것만 세부를 그린다(거리 100~230m 에서 창틀·깊이·줄눈이 사라진다). 모바일은 그 거리를 0.6배로 줄이고, 지평선 건물·옥상 설비·배경 신호 수를 줄인다.

## 버스 모델 — 최종 사용 모델 (2026-11-26 확정)
이 모델을 최종 디자인으로 쓴다. 외부 GLB 로 교체하지 않으며, 형태·재질·바퀴 회전·주행 연출을 그대로 유지한다.
참고 그림 두 장(같은 차량의 전면·후면 3/4)의 비례와 구성을 코드 모델에 옮겼다. 카메라·스크롤·주행 경로·BIT·BIS 연출은 건드리지 않았다.

| 항목 | 값 |
|---|---|
| 기준점 | 차체 한가운데의 노면(y = 0). 앞 +x, 위 +y, 문 쪽 +z. 타이어 바닥이 y = 0 에 닿는다 |
| 크기 | 길이 11.0m · 폭 2.5m · 차체 높이 3.2m(지붕 설비 포함 3.32m) |
| 차축 | 앞 +2.8m, 뒤 −2.6m(축거 5.4m, 앞 오버행 2.7m, 뒤 오버행 2.9m) · 타이어 지름 0.96m(`BUS.wheelRadius` 0.48, 이전과 같음) |
| 신호점 | `SIGNAL` = 지붕 앞쪽 안테나 끝(3.92, 3.36, 0.42) |

- **차체**: 단면(지붕 쪽은 크게, 바닥 쪽은 작게 둥근 상자)을 길이 방향으로 이은 한 장의 곡면. 앞뒤는 평면도에서 모서리가 둥글게 감기고, 앞유리는 뒤로 누웠다.
- **도색·유리·문**: 덧붙인 판이 아니라 곡면을 펼친 좌표 `(u, y)` 에서 수식으로 그린다(`LAYOUT`, `liveryMain()`). 깊은 청색 도장 / 검은 유광 창 띠 / 어두운 유리 / 무광(문틀·통풍구·아랫단)이
  같은 면 위에서 재질만 달라져 반사가 끊기지 않고, 가까이에서도 경계가 선명하다. 참고 그림의 검은 윤곽선은 넣지 않았다.
- **문과 창**: 문 쪽에만 앞문(앞바퀴 앞)과 중간 승하차문이 있다. 반대쪽은 운전석 창과 여섯 칸의 창뿐이다.
- **유리 안쪽**: 시선에 따라 어긋나 보이는 얕은 실내(천장등·좌석·기둥·운전대)로 암시한다. 실제 실내 모델은 아니다.
- **바퀴집**: 차체를 실제로 뚫고(`discard`) 깊이 0.7m 의 어두운 통과 테를 넣었다. 바퀴는 차체와 분리된 네 묶음이고 뒤는 복륜이다. 림·허브·너트 10개·통풍구 8개·드럼.
- **따로 만든 부품**: 전조등(하향·상향·방향지시), 주간등, 세로로 놓인 후미등, 사이드미러, 와이퍼 두 개, 행선지 표시, 지붕 덮개·환기구·냉방 장치, 통풍구.
- **넣지 않은 것**: 제조사 로고, 광고, 워터마크, 번호판·회사명 글자(번호판 자리는 글자 없이 비워 둠). 행선지 표시의 `01 LIVEBUS` 는 BIT·BIS 와 같은 시연용 노선이다.
- **비교**: `/concept-b.html?bus=v1`(이전 모델로 같은 장면), `/bus-preview.html`(모델만 돌려 보기, 이전 모델 전환 버튼). 이전 상태의 파일은 `_backup_2026-11-26_before-bus-model/` 에도 있다.
