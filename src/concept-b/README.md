# LIVEBUS 비주얼 콘셉트 B — LIVE FIELD

검정 공간에 떠 있는 청색 입자 조형물. 커서와 스크롤에 반응한다.
기존 홈페이지(`index.html`)와는 완전히 따로 있는 화면이다. 서로 파일을 공유하지 않는다.

## 보기
개발 서버(`npm run dev`)를 띄우고 `/concept-b.html` 을 연다. WebGL2 가 필요하다.
(`vite build` 대상에는 넣지 않았다. 배포하려면 `vite.config.js` 의 입력에 `concept-b.html` 을 추가한다.)

## 지금 구현된 범위(1차)
- 첫 화면: 작은 신호가 주 리본을 따라 지나가고, 지나간 자리에서 조형물이 드러난다. 로고와 조작 안내만 있다.
- 커서: 가까운 표면만 휘고, 안쪽 심선이 드러난다. 떠나면 관성으로 돌아온다. 빠를수록 조금 더 크게 반응한다.
- 누름·해제: 누르는 동안 주변이 커서 쪽으로 모이고(최대치 제한), 놓으면 얇은 파동이 퍼지며 지나간 자리의 안쪽 선이 잠깐 또렷해진다.
- 스크롤: 조형물 → 버스 실루엣(차체·창문·문·바퀴). 멈추면 그 상태로 머물고, 올리면 되돌아간다.
- 아직 없는 것: 버스 → 도시 연결망(카메라 통과) → 마지막 로고 구간.

## 파일
```
concept-b.html                 마크업(로고 SVG 포함)
src/concept-b/concept-b.css    화면 글자·커서·등장
src/concept-b/main.js          WebGL2 그리기, 입력, 스크롤, 등장, 품질 조절
src/concept-b/shapes.js        입자의 두 목표 형태: 조형물(A), 버스(B)
src/concept-b/field.js         커서 변형 장(격자 용수철)
```

## 구조
- 입자 약 14만 개(좁은 화면 약 8.6만 개). 모든 입자는 리본의 '선' 위에 있고 A·B 두 자리를 가진다.
  같은 선의 이웃은 버스에서도 이웃이라 변형 중에 흩어지거나 순간이동하지 않는다.
- 형태·흐름·밝기는 꼭짓점 셰이더에서 계산한다. 프레임마다 입자를 다시 뿌리지 않는다.
- 커서 반응은 96×54 격자의 변위 장(용수철+감쇠+이웃 결합)을 CPU 에서 풀어 텍스처로 올린다.
  입자는 자기 화면 위치에서 장을 읽는다. 안쪽 구조 입자는 거의 밀리지 않아 표면이 밀리면 드러난다.
- 파동은 최대 4개까지 수식으로 그린다(놓은 위치·세기·경과 시간).
- 스크롤은 전체 형태만, 커서는 그 위의 국소 변형만 담당한다.

## 조정값
- 조형물의 구도: `shapes.js` 의 `RIBBONS`(곡선 제어점·폭·비틀림·선 수), `SCALE_A`, `OFFSET_A`
- 버스: `shapes.js` 의 `WINDOWS`, `WHEELS`, `YAW`, `PITCH`, `busPaths()`
- 커서 반응: `field.js` 의 `K`(용수철), `C`(감쇠), `S`(이웃 결합), `R`(밀어내는 범위), `RG`(끌어모으는 범위)
- 파동 속도·폭·여운: `main.js` 꼭짓점 셰이더의 `front`, `0.045`, `after`
- 스크롤 길이: `concept-b.css` 의 `.scroll-space { height }`
- 밝기: `main.js` 의 `uGain`

## 성능·접근성
- 프레임이 계속 느리면 입자 수(100% → 72% → 50%)와 해상도 배율(2 → 1.5 → 1)을 차례로 낮춘다.
- `prefers-reduced-motion`: 움직임 없는 대표 형태. 스크롤하면 짧은 페이드로 조형물 ↔ 버스가 바뀐다. 커서 변형과 파동은 끈다.
- 터치 환경에서는 사용자 커서를 표시하지 않는다.
- WebGL2 를 쓸 수 없으면 안내 문구만 보여 준다.
